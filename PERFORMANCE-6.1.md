# Vector PNI 6.1 — очистка и производительность

## Результат и границы работы

Изменения выполнены локально на стабильной базе 6.0, коммит dacf4d3527096c27b1655b2b8d1124468d6cc36f. Публикация, push и изменение GitHub Pages не выполнялись.

Подтверждённый выигрыш: подготовка внутренней геометрии быстрее на 32,4% при CPU ×1 и на 18,9% при CPU ×4; raycasting изолированных деталей быстрее на 53,1% / 41,5%. Устойчивого общего прироста FPS не установлено. Снижение JS heap не установлено: кэш занимает дополнительную небольшую память. Геометрия, освещение, материалы и управление сохранены.

Точка отката: локальная ветка `backup/pre-vector-pni-6.1-20261105` на исходном коммите и [ZIP исходников 6.0](qa-artifacts/performance61/stable-6.0-source.zip). SHA256: 03828bbae6057e7377c7e9d934e0f866de460a1035b0a82d363254982700a591. Предыдущие ветки и ZIP 5.2/6.0 не удалены.

## Методика

- Chrome 157.0.8103.38, Windows, ANGLE / Intel UHD Graphics / D3D11; 16 логических CPU по navigator.hardwareConcurrency.
- Две production-сборки: замороженная 6.0 на localhost:5182 и текущая 6.1 на localhost:5175. Исходный snapshot — [baseline-manifest.json](qa-artifacts/performance61/baseline-manifest.json).
- Порядок ABBA: 6.0 → 6.1 → 6.1 → 6.0, отдельные браузерные контексты. CPU ×1 и ×4; CPU throttling не ограничивает GPU.
- Атлас: 15 геометрических узлов одновременно, все 52 раздела и их содержимое созданы. Отдельный компонент «зарядное устройство» остаётся 16-й внешней информационной карточкой. Для повторяющихся двигателей/пропеллеров/ESC используется существующий представитель узла.
- Атлас 1000×900, DPR 1; одинаковые камеры и студийный свет. 400 мс прогрева и ≥1,8 с / ≥60 кадров на режим. Пустой кадр, context loss, GL error и фоновая вкладка исключаются проверкой. Показатели атласа ниже рассчитаны по объединённым межкадровым интервалам двух окон каждой версии.
- Загрузка: свежий контекст, HTTP-кэш выключен, loopback, без имитации интернет-соединения. По два замера на версию/CPU. Готовность главной сцены и первого внутреннего узла наблюдается по реальному состоянию интерфейса.
- JS heap: CDP после явного GC; это не вся RAM процесса и не VRAM. Геометрические ArrayBuffer посчитаны отдельно; текстуры и память драйвера в эти байты не входят.

Исторические 125,18 FPS из другого прогона 6.0 не использованы как непосредственный контроль. Свежая замороженная 6.0 измерялась заново в тех же сценариях.

## Найденные расходы и изменения

1. Профиль CPU показал заметную стоимость повторного побайтного хеширования геометрии при подготовке превью и узлов. Добавлен WeakMap-кэш отпечатков только для завершённой неизменяемой геометрии основной модели. Превью используют те же CPU-атрибуты. Версии атрибутов, их замена, массивы, layout, drawRange и группы проверяются перед повторным использованием ключа. Мутируемая геометрия по умолчанию не регистрируется; проверка совпадения байтов при коллизиях сохранена. Кэш не содержит renderer/GPU handles.
2. Один и тот же материал сериализовался многократно при instancing. Подпись теперь рассчитывается один раз в пределах прохода. Две дублировавшие друг друга функции сравнения материалов внутреннего узла заменены общим `createStudyMaterialKey`; compaction и material pool используют один construction-scoped кэш. Полные точные цвета, параметры и идентичность текстур сохранены; пиксели текстур не сериализуются.
3. Raycaster раньше проверял скрытую геометрию и отбрасывал попадания после расчёта. Теперь переиспользуемый массив кандидатов заполняется через traverseVisible. На одинаковых 1 404 лучах по 52 изолированным разделам ответы до/после полностью совпали, включая leaf и индекс инстанса.
4. Удалено создание промежуточных сплошных корпусов/выводов PCB, старого корпуса контроллера и воздуховода, которые в том же вызове сразу удалялись и заменялись уточнённой геометрией. Сохранены владельцы, имена, смещения разборки и итоговые детали. Устранены **204 лишние construction-операции**, а не 204 видимые детали. Итоговые 162 выбираемые ветви, 388 render meshes и их геометрия совпадают.
5. Удалены неиспользуемый helper `board` и его передача в context60, неиспользуемая локальная переменная `key`, девять устаревших CSS-правил: webgl-error, modal-symbol, spec-source, viewer-error и их вложенные/адаптивные варианты. Действующие detail-error и fallback-стили сохранены.
6. Устаревшие одноразовые `redesign.mjs` и `upgrade-v3.mjs` перенесены из корня в [cleanup-backup](qa-artifacts/performance61/cleanup-backup). Неиспользуемый старый `dist` архивирован в [obsolete-dist.zip](qa-artifacts/performance61/cleanup-backup/obsolete-dist.zip) и удалён из рабочего корня. Нужный Pages-артефакт — pages-dist. Исторические QA-скрипты, тесты, изображения, bench и резервные версии сохранены.
7. Скриншоты двух регрессионных сценариев теперь сохраняются относительными путями в qa-artifacts, вместо абсолютных путей в корень проекта. Версия package.json и корневого lockfile — 6.1.0; новые unit-проверки включены в npm test.

Не добавлены и не удалены зависимости: все текущие зависимости нужны приложению или сборке. C++, C#, WebAssembly, новые материалы, LOD, уменьшение DPR и изменения геометрии не применялись.

Значения CPU ×4 заметно колеблются: в разных режимах новая версия оказывалась как быстрее, так и медленнее; диапазоны повторов перекрываются. Горячий цикл рендеринга не менялся. Эти данные **не доказывают общего прироста FPS**, а разницу средних нельзя объяснять только изменениями кода. Выигрыш подготовки и picking повторился в независимом пробном и финальном парном прогоне.

GPU timer главной сцены: EXT_disjoint_timer_query_webgl2, 78/79 валидных проб без disjoint; медиана 1,499 → 1,521 мс, p95 1,570 → 1,561 мс. Ускорение GPU не установлено. Измерялся настоящий renderer сцены, не предварительный capability probe.

В покое — **0 отрисованных кадров и 0 ожидающих requestAnimationFrame** за окно 1,8 с в обеих версиях. CPU ×4 TaskDuration браузера около 6,01 → 5,86 мс за это окно; это включает инструментацию и не является процентом загрузки системного CPU. Доля системного GPU, энергопотребление и VRAM недоступны. Отсутствие фоновой отрисовки сохранено.

DPR 2 и 3 дополнительно проверены при CPU ×4; основной просмотр сохраняет существующий предел DPR 2, внутренний — 1,6. Новое снижение качества не введено.

## Оставшиеся ограничения

- Надёжный прирост FPS и снижение общей RAM не доказаны; главные улучшения относятся к latency подготовки/выбора.
- 388 вызовов атласа сохранены. Более агрессивное объединение независимых движущихся/выбираемых владельцев требует другой схемы видимости и выбора; в этой версии оно не вводилось.
- GPU time измерен только для главной сцены на имеющейся интегрированной графике; аппаратные GPU utilisation, VRAM, энергопотребление и реальные слабые телефоны не измерены.
- Короткие окна FPS и два замера загрузки чувствительны к планировщику, частоте CPU и прогреву; loopback не воспроизводит GitHub CDN и сеть пользователя.
- Выполненные циклы не являются часовым/многочасовым soak и не доказывают отсутствие любой возможной утечки.
- Степень условности реконструкции AF-18 не изменялась; заводская CAD-точность не заявляется.
- Для выпуска нужен отдельный запрос на публикацию. GitHub Pages не изменён.
